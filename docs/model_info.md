# best.pt 模型元数据分析

记录从参考模型 `best.pt` 中提取出的关键信息，供推理脚本配置参考。

## 分析方法

新版 PyTorch 保存的 `.pt` 文件本质是 **zip 归档**，其中 `best/data.pkl` 是 pickle 流。
pickle 内的短字符串（配置键、类名、路径）以明文存放，因此无需安装 torch 即可解析：

```python
import zipfile
with zipfile.ZipFile("best.pt") as z:
    raw = z.read("best/data.pkl")
# 再自定义 pickle.Unpickler，把未知类替换为 stub，即可取出属性字典
```

对应脚本见仓库外的 `inspect_model2.py`（分析工具，未纳入本仓库）。

## 对推理脚本的影响

### 1. 必须按 pose 模型处理

`results.keypoints.xy` 返回形状 `[N, 4, 2]`，即每个目标 4 个点、每点 (x, y)。
**不可以使用检测框四角代替关键点**，作业明确禁止。

### 2. `[4, 2]` 而非 `[4, 3]`

第三个维度是 **2 不是 3**，说明：

- 模型**只输出关键点坐标，不输出每个点的可见性置信度**
- 因此**无法按"点置信度阈值"过滤关键点**
- 脚本改用坐标合理性判断：坐标为 `(0,0)`，或偏离对应检测框过远的点，判为无效预测并跳过绘制

### 3. 关键点无语义命名

`kpt_names` 里 4 个点都叫 `'0' '1' '2' '3'`，没有"左上/右上"之类的语义。
因此可视化时按 **序号标注**（点旁写 0/1/2/3）比强行命名为"角点"更准确。
若需要连线，默认顺序取 `0-1-2-3-0` 构成四边形轮廓。

### 4. 类别颜色可按阵营区分

由于类别名以 B / R 开头，实际使用时可以把颜色映射改成：

- `B*` → 蓝色系
- `R*` → 红色系

脚本默认按类别 id 生成稳定颜色，如需按阵营配色可修改 `make_color()`。
